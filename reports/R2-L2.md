## 三、数据根钉死验证（D4）

**件**：`tools/verify-data-root.mjs`（201 行）
**设计前提**：**不 import 任何被测模块**——单体 `config.js` 顶层有 `mkdirSync(DATA_DIR)`（`_unpack/resources/app/src/config.js:826`），import 会往禁改面落目录。故走**静态机制 + 磁盘事实 + 表达式求值**三路取证。

| 检查 | 判据 | 失败级别 |
|:--|:--|:--|
| **C1 单体入口** | `electron/main.js` 的 `process.env.QQ_AGENT_DATA_DIR =` 必须早于对 `../src/app.js` 的**动态** `import()`，且无静态 import（静态 import 会先求值 → 注入来不及） | FAIL |
| **C2 单体数据根** | 打包态 = exe 所在目录 `/data`（`main.js:98` portable 规则）；设了 env 时以 env 为准。该目录须真实带 `config.json` + `sessions/` | FAIL（缺目录）/ WARN（缺数据面） |
| **C3a 业务面·空 env** | DATA_DIR 表达式在空 env 下求值 → 与 C2 不同 = 钉死靠注入而非常量 | **WARN** |
| **C3b 业务面·注入 env** | 同上，注入 `QQ_AGENT_DATA_DIR = C2` → 与 C2 不同 = 运行时真跑偏 | **FAIL** |
| 退出码 | 任一 FAIL → `1`；WARN 只出声不挡 | — |

**为什么用两口径**：单体 `main.js:115` 注入 env 后 `:316` 才动态 import 业务面 —— 运行时读的永远是「注入后」的值。只测空 env 会把「靠注入对上」误判成失败；只测注入则掩盖「独立运行会落到别处」。两条都报，判级别看 b。

## 六、卡点与发现（不改卡，交主干裁决）

**1｜业务面 DATA_DIR 是「抄单体表达式」，钉死靠注入不靠常量（WARN）**
`app/src/business/config.js:24` 与单体逐字相同：`process.env.QQ_AGENT_DATA_DIR || path.join(ROOT, \`data${profileSuffix()}\`)`，其中 `ROOT = app/src`。
- 运行时（由 `main.js` 注入 env 后加载）落在 `_unpack/data` ✅
- 独立运行（脚本直跑 / 单测 / 被其他入口引用）落在 **`app/src/data`** —— 往**源码目录**写数据
建议（不在本线写面内，未执行）：业务面把 `DATA_DIR` 改成显式常量（`path.resolve(ROOT, '..', '..', '_unpack', 'data')` 之类）或改写 `ROOT` 基准。改后本脚本 `比对 a` 自动转 OK，不需改脚本。

**2｜`--force` 与补丁链顺序的残留风险**
守卫只挡「默认执行」，不挡「被别的脚本 `import` / `child_process` 调起」。若后续有批量重跑脚本按顺序 spawn 20 个补丁，需显式传 `--force`——否则会**静默全绿而什么都没打**（20 个 RETIRED，exit 0）。实测 `text-grep --force tools/` → 命中 40 行，全部是本线新增的守卫自身（20 × 注释行 `:3` + 20 × 判定行 `:4`），`tools/` 内无批量调用者；跨目录调用者本线未核（写面外），登记为后续留意点。

**3｜`cache-diag.mjs` 与重标定脚本的漂移面**
两者同口径但两份实现。漂移判据 = 基线 `caliber` 字段与 `cache-diag.mjs` 头部口径行；任一侧改字段必须同步另一侧（脚本头已写明）。若日后要收成单实现，把 `cache-diag.mjs` 的统计段抽成可 import 的函数即可——本次不做，避免动 R0 既有工具面。

**4｜L1 并行产物的观测（非本线职责，仅记录）**
执行期间 `app/src/business/config.js` 已由 L1 落盘（本线只读观测）。本线脚本已能直接验收它，`C3b` 口径当场通过。
