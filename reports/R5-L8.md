## 三、实现要点

### 3.1 骨架形态（为什么不照抄原版的整页重建）

原版 `06-settings-render.js:88-152` 是「`state.settingsSection` 一变就把 `#settings-form` 整个 `innerHTML` 重建」，配套写了渲染守卫（`settingsGuard.pending`）、焦点快照恢复、滚动位置保持三段补丁。这些补丁存在的原因正是**整页重建**这个做法。

本块按 `_index.md` §3.2 的契约换成「`mount` 建一次骨架，`renderBody` 只换右侧 pane-body 的内容」——重建面缩到分节体内，上方侧栏与卡头不动，因此不需要那三段守卫。代价是每次切分节都重绘分节体（表单在途输入会丢），处置：把「切分节」显式写在每次写回成功之后（`save()` 末尾 `renderBody()`），未保存输入由 `change` 事件即写回兜住（输入框都是 `onchange` 触发，不靠按钮）。

### 3.2 `(mode, effort)` 二维压一维（`settings-sections.js:262-286`）

原版 `:833-851` 把 `thinkingMode`（off/auto/on）+ `thinkingEffort`（off/low/…/max）压成一个下拉，其中 **`on` 且 effort 为空** 是独立档 `on-noeffort`。这条不能折进「默认」——折进去就把"明确开启"静默改写成 `auto`。本块照抄这个分档，写回走 `thinkingPatchOf()` 四支（`:274-280`），与原版 `saveConfig` 的 chat 分支同构。

### 3.3 密钥字段的「留空 = 不改」口径（`settings-sections.js:96-113`）

业务面 `sanitizeConfig`（`app/src/business/app.js:1290-1299`）把 `apiKey` **删字段**并补 `hasApiKey`，不回传空串——因为回传空串会在 `deepMerge` 里覆盖真 Key。前端因此：① 密钥框值恒为空；② `placeholder` 显示「已保存（不显示；留空 = 不改）」或「未保存」；③ 提交时 `if (o.secret && raw === '') return;` 直接不写。三处同源，缺一处就会造出「点一次保存就把 Key 清空」。

### 3.4 `store.peakSchedule` 的部分写合并

`updateConfig`（`config.js:817-848`）走 `deepMerge`，所以写 `{store:{peakSchedule:{peak:{start:'08:00'}}}}` 只改 `start`，同级的 `end` / `sliderPos` / `valley` 原样保留。本块据此把峰谷四项拆成四笔独立写回（`settings-sections.js:466-476`），不整体回传该字段——整体回传等于把 `valley.start/end` 这两个已退役字段复活。

### 3.5 提供商目录只用于「显示名」

`GET /api/biz/providers`（`routes.js:394`）拿到的 `modelNames` 只用于把模型 id 显示成人名。取不到时**不阻塞表单**：退化成裸 id 输入框，并把「（未取到目录）」写在字段说明里（`settings-sections.js:190-196`）。这条是为了让「业务面可达但 providers 端点坏」时页面仍然可用。
