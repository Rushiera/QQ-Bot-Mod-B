### 三、改动面细节

**① 切换视图形态**：分段控件（两个 `btn small`，选中态加 `primary`），文案带条数——「现行 165」「归档 71」。放群记区 `pane-head` 里，紧接标题。切到归档时：加一行灰字说明「归档池只读（按天追加的 JSONL）」，隐藏「＋ 添加群记」，行渲染换成只读分支（无「改 / 删」按钮、显示「归档于 MM-DD HH:mm」）。

**② 归档数据源**：直接用详情端点已给的 `groupArchived`（`routes.js:1335`，`limit: 500`）+ 计数 `archiveStats.group`（不受 limit 影响）。二者在本轮基线一致（71 / 71）；若归档涨过 500，条数按钮取 `archiveStats.group`（真实总数），列表只到 500——代码注释已写明这条口径差异。

**③ 要点端点形态**：`GET /api/memory-files/<group|private>_<id>/summary` → `{ chatKey, summary }`，`summary` 为 `readSessionSummary()` 原样（`{summary, createdAt, rollovers, messages}`）或 `null`。选 `null` 而不用 404：让「本会话还没产出要点」与「端点不可用」在页面上可区分（后者走 `fail()` 红字）。

**④ 取数时序**：`loadDetail` 改成 `Promise.all` 并行取详情与要点——两个端点互不依赖，串行会把首屏拖成两跳。要点失败只让要点区报错，不牵连整个详情面。

## 根因

**这两项为什么连挂两轮（R5-L5 记未做 → R7-L3 未派 → R8-L2）**

1. **数据早就齐了，缺的是渲染面**——详情端点从 `[qqagent-memory-patch:no-throttle-routes-detail]` 起就带 `groupArchived` / `archiveStats`，页面 `fileRow`（左栏）甚至已经在显示「归档 N 条」（`memory.js:316-322`），但右栏群记区只读 `group` 一池。缺口在「有数据、没入口」，不是在取数链路上。所以本项是纯前端工作量，不需碰路由。
2. **要点是「后端有读函数、没人调」**——`readSessionSummary` 自会话状态层落地起就存在且已 `export`，`orchestrator.js:32` 也在用，唯独 `routes.js` 没 import 它，于是没有任何 HTTP 端点能取到。这是典型的「能力层齐备、接线层缺一跳」，与 R7-L2 报的 PUT 双闸同族——**声明有 ≠ 可达**。
3. **为什么之前一直没被排上**：R5-L5 交付时把「切换视图 + 要点展示」明确写成未做项，R7 排到 L3 但二批线在换相处丢了（`tasks/R7.md` §五 / `reports/R7-verdict.md`）。本轮是这条欠账第三次被派——**判据口径按 R7-L2 已改后的实现面校准**（旧行号全部作废）才落得下来。
