## 四、卡点（按 §0-5：写清，不改卡）

**1）任务卡只要求加 `ws`，实际必须加三个包（已落盘，需主干追认）**

`app/src/business/app.js:23` 静态 import `./telemetry.js`（该文件**不存在**，D5-2 判退役但 L1 补搬未删 import）——这条不属于本线写面，未动。除此之外：

**2）`telemetry.js` 缺失仍在 import 面上（L1 未收线，非本线可动）**

`app/src/business/app.js:23` 的 `import { startTelemetryLoop } from './telemetry.js';` 在磁盘上无对应文件，`app/src/business/` 走 `node --check` 时不解析模块（语法层通过），但真 import 必崩。现脚本对这类失败给的是具名「业务面源码缺文件：./telemetry.js」——**这正是本轮 M4 要的效果**：不再是 `ERR_MODULE_NOT_FOUND` 栈。待 L1 按 D5-2 删 import + 删调用点后自然闭合。

**3）脚本跑绿会写生产数据根（§0-B 口径冲突，未修，待裁）**

§0-B 要求「`data/` 与 `_unpack/data/` 一律 `mkdtemp` 重定向；禁写生产数据根」。现脚本硬钉 `process.env.QQ_AGENT_DATA_DIR = _unpack/data`（原实现如此），跑一次重写 `session-index-cache.json` 与 `price-feed-cache.json` 两份派生物（见 §二 补充实测表）。本轮按卡只修「缺依赖的具名错误」，**未改数据根口径**——重定向需 `mkdtemp` + 拷一份 config 与 memory 骨架，且会让「冒烟到的配置」与生产配置分叉（脚本判据本就是「用当前配置起一次」）。两个方向待主干拍：① 保持现状，卡面为该脚本开一条具名例外；② 改 `mkdtemp` 并只读拷 `config.json`（判据退化为「配置可加载」）。

**4）`verify-qqagent-boot.mjs` 定位是「单体业务面冒烟」，非单体装配根冒烟**
