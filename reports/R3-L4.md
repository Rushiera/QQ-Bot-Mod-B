## ② `tools/verify-data-root.mjs` · `readDataDirExpr` 括号配平（本线完成）

### 改法

原实现（`:56-66`）只取 `const DATA_DIR =` **那一行**做右值：

```js
const expr = lines[idx].replace(/^[\s\S]*?const\s+DATA_DIR\s*=\s*/, '').replace(/;\s*$/, '').trim();
```

归位后业务面的 `DATA_DIR` 是 IIFE 多行块（`app/src/business/config.js:30-35`），只取一行拿到 `(() => {` → `vm` 求值必然 `Unexpected end of input`（R2-L4 卡点 3）。

现实现改为**按括号配平扫描**，纯读取、不 `eval` 整文件：

| 件 | 做法 |
|:--|:--|
| `readDataDirExpr(file)` | 正则定位 `const DATA_DIR =` 的**字符偏移**（不再按行切）；`line` 由该偏移前的换行数算出（声明所在行，1 起）；右值交给 `scanBalancedExpr` |
| `scanBalancedExpr(text, start)` | 从偏移起逐字符累积，维护 `(){}[]` 四种括号栈；**栈空且遇顶层 `;`** 即收口返回；到文件尾仍未配平 → 返回 `null` |
| 跳过扫描陷阱的三件 | 行注释 `//`、块注释 `/* */`、字符串 `'` `"` 反引号（模板内 `${…}` 递归配平）——否则注释里的括号会把栈带偏 |
| 正则字面量 | `skipRegexLiteral`：仅在上一个有效字符是运算符位（`=(,:[!&|?{};+-*%<>~^`）时才当正则处理，避免把除号误吃；遇换行即中止 |
| 失败形态 | 未配平 → `{ error: '第 N 行起的表达式括号未配平（(){}[] 四种都计）' }`；声明不存在 → `null`。两种都不猜、不回落 |

判据面同时收紧（原实现把 C3a 与 C3b 包在同一个 `try` 里，任何一处在抛都会让两项一起判「表达式无法求值」）：

- **C3**（读表达式）：先报 `文件:行 · 表达式`（折行压平、>160 字符截断 + `…`），再做求值。
- **C3a**（空 env）：业务面空 env 下**具名抛错拒绝启动**（错误串含「未注入」/`QQ_AGENT_DATA_DIR`）判 **OK** 并说明「比常量钉死更硬」；抛出**非预期**错误才判 FAIL。
- **C3b**（注入 env）：这才是运行时实际目录，失败即 FAIL，不猜、不回落。
- **比对 a/b**：原先 `if (monoRoot && bareRoot && injectedRoot)` 在 C3a 抛错时整段静默跳过（未比对伪装成已比对）；现改为 `if (monoRoot && injectedRoot)` 判定 b，a 项在 `bareRoot` 为空时明确记「空 env 拒绝启动 —— 比常量钉死更硬」。

文件头注释同步补两条口径：括号配平取值（卡点 3 的成因）· 空 env 具名抛错记 OK 的例外。
