## 一、结论（≤5 行）

1. **ref §A/§B/§C 18 条全部落位，无孤儿行**；三条补丁脚本共 **29 处注入点**（botguard 19 / cwd 4 / navigator 6），与脚本内 `patch(` / `patchVariants(` / `copyModule(` 调用数逐一相等。
2. **出站重叠在协议调用点，不在闸门**：单体 4 个出站函数（`say` / `sayImage` / `sayRecord` / `sayAt`）与业务面 `SendQueue` 打的是同一个 OneBot action `send_group_msg`；合并后**业务面 B1–B8 全保留**，单体 `say*` 退化为薄壳（保留 `send_group_msg` 调用能力，去掉自成体系的语义）。
3. **入站是缺口不是重叠**：单体只读 `raw_message`（`app/src/navigator/index.js:432`），无段解析 / 引用解析 / @ 名片 / 语音转写 / 转发展开（`transcribe`、`get_msg` 全库 0 命中）——C1–C5 整体搬入 `app/src/business/inbound/`。
4. **底座取舍 = 保留「WS 收事件 + HTTP 发 API」双通道与 action 分档超时**：单体是 WS 单通道 + 固定 15s（`app/src/onebot/client.js:162`），业务面发送类 60s / 查询类 15s（`onebot.js:276`）——2026-09 实测 1.9MB 图在 15s 下稳定超时，这是保留业务面形态的实证理由。
5. **cwd 补丁 4 点中 2 点已失效**（`启动QQAgent.bat` / `.vbs` 于 2026-10-12 被 `tools/apply-entry.mjs` 重写成单体别名入口，锚点消失，重跑会在第 3 点抛错）——见 §四卡点 1，属主干裁决项。

## 二之三 出站发送面重叠点专答（验收第 4 条）

| 维度 | 业务面出站 | 单体出站 | 重叠？ | 合并后 |
|:--|:--|:--|:--:|:--|
| 协议调用 | `onebot.sendSegments` → `call('send_group_msg')`（`onebot.js:319-325, 269`） | `say/sayImage/sayRecord/sayAt` → `onebot.call('send_group_msg')`（`navigator/index.js:473/498/521/545`） | ✅ **同一 action、同一协议端、同一账号** | 统一走 `business/sender/queue.js`，协议调用只留一处 |
| 会话串行 | 每会话链（`sender.js:92-95`） | 无（并发直发） | 重叠在「同一群」上 | 保留业务面链，单体 `say*` 入链 |
| 节拍 / 限频 / 去重 | 有（B2/B3/B4） | 无 | 不重叠（单体缺） | 全保留 |
| 切分 / MD / CQ 转义 | 有（B5/B6） | 无 | 不重叠 | 全保留 |
| 路径转 URI | `toFileUri`（`sender.js:42-60`，编码 + UNC + `#?`） | 手拼 `file:///` + 反斜杠替换（`navigator/index.js:495`） | ⚠️ **语义重叠且单体更弱** | 保留业务面版本；单体手拼版删除 |
| 发出记账 | `self=true` 写 store（B8） | 无 | 不重叠 | 保留 |
| 闸门（配额/硬限/botGuard/rapport） | 有 | 无 | 不重叠 | 保留；VIP 旁路（navigator 3 点）保留为单条开关 |

**结论（谁保留）**：`send_group_msg` 调用能力归单体（薄壳），**出站语义全部归业务面搬来的 `business/sender/`**。单体 `say/sayImage/sayRecord/sayAt` 只保留「组装段 + 调队列 + 返结果」三段，队列内依次过 botGuard→rapport→硬限→配额→去重→切分→转义→节拍→发送→记账。
