## 一、做了什么

把一个 43 行桩换成 653 行真实现：**左栏群会话全量列表 + 右栏选中群的消息存档 + 该群会话运行记录**。

| 面 | 实现 | 位置 |
|:--|:--|:--|
| 左栏列表 | `state.chats` 按 `lastTs` 倒序全量渲染，**无分页无截断**；行内含群名 / 群键 / 存档条数 / 未读 / 前情段数 / 最近会话状态徽标 / 最近消息时间 | `sessions.js:267`（`chatRow`）· `:293`（`renderList`） |
| 过滤 | 输入框按「群键 ∪ 群名」大小写不敏感包含匹配，只影响显示不影响取数 | `sessions.js:252`（`matchFilter`） |
| 右栏消息 | 选群 → `GET /api/biz/chats/<group_xxx>/messages`，逐条渲发送者 / 时间 / 媒体数 / 未读 / 正文 | `sessions.js:453`（`loadMessages`）· `:329`（`messageRow`） |
| 右栏会话记录 | 该群 `sessions` 摘要全量列出（id / 状态 / 轮数 / in-out token / 模型 / 时间 / 触发语），按开始时间倒序 | `sessions.js:348`（`sessionRow`）· `:409`（`renderDetail`） |
| 消息条数档位 | `全部 / 最近 100 / 最近 300`；选「全部」时不带 `limit` 参数（交给业务面默认上限 1048576） | `sessions.js:242`（`limitQuery`） |
| 头部动作 | 「刷新消息」「压缩前情」两个按钮 + 档位下拉；头部同时回显存档数 / 会话记录数 / 已载入消息数 | `sessions.js:369`（`detailHead`） |
| 空态 / 失败态 | `empty()` 走三处（无群 / 无匹配 / 无消息）；`fail()` 文案恒含 `127.0.0.1:3210` | `sessions.js:293-320` · `:409-450` |
| 降级 | `window.__ui` 缺 `el` / `empty` / `fail` / `fmtTime` / `fmtNum` 时用块内等价实现兜底；缺 `api` 时页面显「契约未就绪（`window.__ui.api` 缺失）」而非白屏 | `sessions.js:68-183` · `:455-459` |

**取数口径**：`/api/biz/sessions` 一次拿 `chats`（列表）+ `sessions`（运行记录），`/api/biz/chats` 只取群名（`chatName`，与 L3 存档页同源）。两次并行，失败任一条走失败态。

**并发与竞态**：`refresh()` 单飞（`inflight` 句柄复用同一 Promise）；消息请求带递增 `seq`，切群后迟到响应按序号丢弃，不覆盖新群的数据。

## 四、口径说明（与卡文的一处措辞差异，不是偏离）

卡 §四 L2 必读写「点选后 `/api/biz/chats?chat=<群号>`」，而 §3.2 映射表与验收② 写的是 `/api/biz/chats/group_<群号>/messages`。实现按**后者**（§3.2 + 验收② 一致的那条），理由：

- 业务面 `routes.js:1463` 的正则路由是 `^/api/chats/(group|private)_(\d+)/messages$`——`?chat=` 形态在该文件里不存在（`/api/chats` 只接受无参 GET，见 `:1274`）。
- 实测 `/api/chats?chat=<群号>` 会返回全量群列表而非某群消息，语义不符。

`chatKey` → 路径段转换：`group:361820329` → `group_361820329`（仅冒号换下划线，不拆参、不解析），与代理层「纯前缀替换、不解析路径」的契约（`_index.md` §3.3）一致。
